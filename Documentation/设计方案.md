# Trace：Alamofire 网络诊断面板设计 v0.1

Trace 为暂定项目名，发布前检查重名。本文为设计方案，尚未实现原生包。

## 产品定位

面向使用 Alamofire 的 iOS 开发者，在 App 内查看最近请求、HTTP 校验结果和解码失败原因。首版服务开发调试，不作为生产环境网络监控 SDK。配套示例 App，包通过 Swift Package Manager 集成。

## 首版界面

### 请求列表

- 标题、记录状态、设置入口。
- 路径及域名搜索；全部、失败、慢请求（默认超过 1 秒）筛选。
- 每行展示方法、路径、结果标签、开始时间、总耗时及响应体字节数。
- 最新请求在前；查看详情不因新请求到达而跳转。
- 区分进行中、成功、HTTP 校验失败、解码失败、网络失败与主动取消；主动取消不默认计入失败。
- 暂停仅停止接收新请求记录，已开始记录的请求继续补齐终态；继续不追补暂停期间的请求。
- 空状态分别提示尚无请求、没有匹配结果和已暂停。仅监测绑定了 monitor 的 Session。

### 请求详情

- 摘要：方法、完整脱敏 URL、HTTP 状态、总耗时、响应体大小。
- 请求页：请求头、查询参数、受支持的请求体；缺失与被隐藏分别显示。
- 响应页：响应头、格式化 JSON 或文本；明确标注未采集、已截断、二进制不支持。
- 诊断页：结构化呈现错误类别及底层信息；能够提取 DecodingError 时显示字段路径和类型信息，不能提取时保留可用错误信息。
- HTTP 200 + 解码失败单独标注；HTTP 成功不等于业务成功。
- 分享入口先显示脱敏预览，随后由用户显式调用系统分享；不自动上传。
- 首版不提供请求重放。

### 设置

- 响应体采集开关，默认开启，按媒体类型允许文本和 JSON。
- 默认保留 200 条，可选 100 / 200 / 500；超出移除最早记录。
- 单条请求体和响应体各最多保留 64 KiB，全局正文预算默认 8 MiB；超出优先移除最早的正文，保留元数据并标注原因。
- 紧凑列表开关；清空记录需要二次确认。
- 显示脱敏规则与仅内存存储状态。敏感字段规则由集成方配置，面板不提供一键关闭脱敏。
- 调整采集配置仅影响后续采集，不恢复已经丢弃的数据。

## 首版不支持

上传 / 下载正文、multipart、流式响应正文、WebSocket、后台恢复、持久化历史、跨设备同步、修改请求、自动修复、业务登录管理。

## 集成 API 草案

以下仅表示预期接入体验，不是已存在的 API：

```swift
#if DEBUG
let diagnostics = NetworkDiagnostics(configuration: .development)
let session = Session(eventMonitors: [diagnostics.monitor])
// 将 NetworkDiagnosticsView(store: diagnostics.store) 放入宿主调试页面。
#else
let session = Session()
#endif
```

由宿主决定面板入口，首版不自动注入悬浮窗、不扫描全部 Session、不改变请求流程。建议通过条件编译让发布构建不创建记录器及面板。

## 模块与数据流

1. AlamofireAdapter：EventMonitor 适配，按 request.id 关联事件，区分请求与重试尝试。
2. DiagnosticsCore：记录模型、事件归并、脱敏、容量控制及报告生成。
3. DiagnosticsUI：SwiftUI 列表、详情、设置与分享入口。
4. ExampleApp：模拟成功、HTTP 错误、解码错误、超时、取消、重试及大响应场景。

适配器接收事件后先筛选和脱敏，再进入有界记录存储，UI 仅订阅脱敏快照。并发事件通过受控顺序进入隔离存储；UI 更新在 MainActor，批量合并，避免每个事件都刷新整个列表。具体并发实现和模块依赖通过最小技术验证确定。

事件监控是观察机制。URLRequest 不保证包含可读取正文，尤其是流式或文件请求；无法取得时明确显示不支持。响应采集不得为诊断额外读取流或破坏正常处理流程。

## 记录模型

- ID、开始时间、请求尝试列表、进行中 / 终态。
- 脱敏 URL、方法、头信息、受限正文、正文采集状态。
- HTTP 状态、可用的 URLSessionTaskMetrics、错误类别、可选解码路径。
- 区分原始字节数、捕获字节数和实际网络传输指标。指标缺失时显示不可用，不推算 DNS / TLS 耗时。
- 总耗时定义为请求开始到终态，含重试；尝试次数与逐次信息单独记录。

## 脱敏与性能约束

- 默认隐藏 Authorization、Proxy-Authorization、Cookie、Set-Cookie。
- 配置敏感查询参数和 JSON 字段，如 password、accessToken、refreshToken、email；请求和响应使用同一规则。
- 任意自由文本无法保证自动完整脱敏。无法可靠处理的正文不进入可分享报告；过大或截断 JSON 不直接作为“已脱敏 JSON”保存。
- 分享采用允许字段策略，复用同一脱敏数据，不重新访问原始请求。
- 无网络上传，无磁盘持久化；仅 DEBUG 也不意味着数据天然安全。
- 网络记录队列不可无限堆积。压力过大时跳过正文或丢弃记录，并显示丢弃数量。
- 正文的复制 / 脱敏本身存在开销，需测量，不能承诺零开销。

## 验收场景

- 并发请求、重试、取消、超时不会造成记录串联或悬挂。
- HTTP 成功但解码失败能准确区分，非 DecodingError 不编造字段路径。
- 请求头、URL 查询、请求 JSON 和响应 JSON 中配置的敏感值不会出现在记录与分享报告中。
- 记录数、正文大小及全局预算均有上限；不支持的正文有明确标识。
- 暂停、筛选、清空和查看详情期间持续接收事件，行为一致。
- 大字体、深色模式、VoiceOver、空状态和长 URL 均能使用。
- Release 示例构建不创建诊断记录器和面板。

## 开发顺序

1. 技术验证：获取三个请求的终态，验证底层错误与响应体是否可用。
2. 实现脱敏和有界存储，先通过核心测试。
3. 完成 SwiftUI 列表与详情。
4. 加入配置、报告预览和分享。
5. 真机评估开销、完善文档与示例，发布 0.1.0。

发布前另行验证同类工具、差异化需求、许可证和项目名。
