# 第一课：让一条请求变得可观察

目标：运行示例，理解 Session、monitor、store、View 各自负责什么。

## 1. 运行

打开 `Examples/TraceExample/TraceExample.xcodeproj`，选择 TraceExample 和 iPhone 模拟器，运行。首次解析依赖需要网络，模拟接口本身不需要网络。

## 2. 按这个顺序读源码

1. `Examples/TraceExample/TraceExampleApp.swift`：找到 `DemoModel.init()`，查看如何把 monitor 交给 Session。
2. `Sources/TraceAlamofire/NetworkDiagnostics.swift`：找到 `requestDidResume`、`requestDidFinish` 和 `didParseResponse`。
3. `Sources/TraceCore/DiagnosticsStore.swift`：查看事件怎样变成记录，以及记录怎样被脱敏和限制容量。
4. `Sources/TraceUI/NetworkDiagnosticsView.swift`：查看 SwiftUI 如何根据记录显示列表。

数据流：模拟 App → Alamofire Session → URLProtocol 模拟响应 → EventMonitor → 脱敏存储 → SwiftUI 面板。

## 3. 从 JavaScript 迁移过来的概念

| Swift | 你熟悉的概念 |
|---|---|
| `let` / `var` | 不可变绑定 / 可变变量；结构体的值语义还需单独理解 |
| `String?` | 可能没有值的字符串；使用前必须处理 nil |
| `struct Feed: Decodable` | 明确的数据模型，解码时真的会检查响应结构 |
| `async` / `await` | 类似异步函数；Swift 还有任务取消与隔离规则 |
| `protocol EventMonitor` | 一组约定的回调接口 |
| `@StateObject` / `@Published` | 让状态变化驱动 UI，具体生命周期与 React 不同 |

## 4. 做一个小修改

在 DemoURLProtocol 中把 feed 的 `"title": null` 改成 `"title": "My first Swift change"`，重新运行。

预期：`/v1/feed` 从解析失败变为成功。然后把 title 改成数字，查看类型不匹配错误，比较与 null 的错误有何不同。

## 5. 验证理解

- 为什么 HTTP 200 仍然可能显示解析失败？
- 为什么换一个没有绑定 monitor 的 Session 后，面板就不记录它？
- 为什么不能在调试工具中直接保存 `error.localizedDescription` 和原始 JSON？
- 如果不用 `.validate()`，401 是否必然进入 HTTP 错误分类？

这一课先不改架构。能运行、能修改、能解释数据流，就是完成标准。
